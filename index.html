WHAT IS AND IS NOT SHARED
The bigger picture.
Google sign-in is not a key to your whole Google account. Other Google services have their own APIs and separate permissions.

          

            
✉
Gmail messages
Extra approval required
Access to inbox contents requires Gmail-specific permissions and is not enabled in this website.

            
▧
Drive files
Extra approval required
Viewing files or file metadata requires separate Google Drive permissions. This website does not request them.

            
▦
Calendar events
Extra approval required
Calendar data needs its own scope and separate consent. This website does not request it.

            
◌
Google Contacts
Extra approval required
Other people's contact details require a separate permission; optional profile access here does not request contacts.

            
⊙
Passwords & private account security
Not shared by sign-in
Your Google password is never given to a website by the Google OAuth sign-in flow.

            
⌾
Everything Google stores
No single all-data permission
No basic OAuth token reveals the full Google account archive. You can use Google's own data export tools for a broader personal record.

IN CONTROL
Privacy & setup.
A transparent account-data explorer. Each visitor can see only the data returned for the Google account they choose to authorize.

          
How this app handles data
Limited retention
  • Google login runs on Google's own pages.
  • The backend verifies your Google ID token.
  • Access tokens are used briefly then discarded.
  • No Gmail or Drive data is requested.
  • Signed-in account details are stored temporarily in a server-side session (Redis on the public website). The session expires after one hour.
  • Raw responses are shown only to the browser in the active signed-in session.
  • Signing out ends the local session; it does not revoke Google's earlier consent.
Disconnect and manage access
Sign out here to erase the local session. To revoke the Google permissions granted to this app, visit your Google Account's third-party connections page.
Manage Google account connections ↗
Public hosting requires HTTPS, a private Redis session store, secure Google credentials, and compliance with Google’s verification requirements. The privacy policy should be reviewed and customized before launch.

          
GET STARTED
Deploy using GitHub and Render
  1. Upload these project files to a GitHub repository. Keep .env out of GitHub.
  2. Create a private Render Key Value instance for temporary sessions.
  3. Connect the GitHub repository to a Render Web Service, or use the included render.yaml blueprint.
  4. In Render, set the Google Client ID and Secret, GOOGLE_REDIRECT_URI, and REDIS_URL as environment variables.
  5. In Google Cloud, authorize your exact HTTPS callback address: https://YOUR-SITE.onrender.com/auth/google/callback.
  6. Read DEPLOY_GITHUB_RENDER.md for the complete deployment and publishing checklist.
See DEPLOY_GITHUB_RENDER.md for the complete setup. Privacy policy template ↗
